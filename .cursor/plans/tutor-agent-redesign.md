# Tutor Agent Redesign — Implementation Summary (v1, archived)

## Problem

The tutor felt like a **quiz machine**: pre-generated 2–5 questions per learning goal, cycled through them sequentially, two separate interrupt types (`present_question` vs `socratic_response`) that felt asymmetric. Responses were predictable and formulaic — not like a real tutor.

## Goal

Make the conversation feel like a **Socratic office-hours discussion**: one anchor problem per goal, short back-and-forth "jabs" where the tutor reads partial understanding and probes the specific thing they're missing. Student mental model should be explicit and drive the next question.

### New Flow

```
START → initialize_session → select_next_goal → generate_anchor_problem
  → tutor_turn [interrupt]  ←──────────────────────────────────────────┐
        ↓ (student responds)                                            │
  evaluate_and_update_model                                             │
    ↙           ↓           ↘                                           │
"mastered"  "continue"    "give_up"                                    │
    ↓           └───────────────────────────────────────────────────────┘
    ↓
mark_goal_complete → [more goals?] → select_next_goal OR generate_summary → END
```

## Key Design Decisions

### 1. Anchor Problem (one per goal)
Each learning goal gets **one multi-step worked example** from the lecture (e.g., "Walk me through MLE on the taxi arrivals data: 3, 5, 2, 4, 6"). Working through the problem requires demonstrating all competencies in sequence. The `learning_goals.jinja` prompt was updated to generate **sequential competencies** that map onto steps of a single worked problem.

### 2. Substantive Student Model
Per competency, the student model now tracks:
- **Accumulated evidence list** — each exchange appends a new observation (not overwritten)
- **Competing hypotheses** — multiple theories about *why* the gap exists, each with confidence (high/medium/low)
- **Gap description** — specifically what's missing
- **active_probe_target** — the weakest unresolved competency, used by `tutor_turn` to target its question

### 3. Variable Response Styles (5 modes)

| Mode | When | Style |
|------|------|-------|
| `open` | First exchange on goal | Casual intro to anchor problem (uses `opening_framing` directly) |
| `probe` | Response too thin to evaluate | 1-sentence clarifying question (generated by evaluate, delivered directly) |
| `nudge` | Student is close (weakest score ≥ 0.55) | 1 sentence, casual push — "can you say a bit more about X?" |
| `socratic` | Clear gap, hypothesis to target (score < 0.55) | 2–3 sentences: acknowledge right + ONE targeted question |
| `explain` | Stagnation / max exchanges reached | 2–3 paragraphs, direct explanation from `goal.takeaways` |

Routing thresholds: `NUDGE_THRESHOLD = 0.55`, `MAX_EXCHANGES_BEFORE_EXPLAIN = 6`

### 4. Probe-to-Evaluate Loop
When a student response is too brief to score confidently, `evaluate_and_update_model` sets `needs_more_info=True` and generates a `probe_question`. `tutor_turn` delivers it directly (no LLM call). The next response loops back to a full evaluation. Prevents spurious low scores from thin responses.

## Verification Checklist

1. Start a session (`POST /tutor/sessions`) — opening message should be natural, not "Question 1: ..."
2. Submit a partial response — tutor reply should be ≤3 sentences and target the specific gap
3. Submit a very short response ("I don't know") — should get a 1-sentence probe question back
4. Submit near-correct response — should get a 1-sentence nudge, not a full Socratic question
5. Let stagnation trigger (no progress for 2+ turns) — tutor should switch to direct explanation
6. Check `GET /tutor/sessions/{id}/trajectory` — competency scores + evidence still tracked per exchange
7. `uv run pytest tests/test_graphs.py -v` — all 45 tests pass
